ERP 系统需求文档
1. 项目背景
企业在日常经营中涉及采购、销售、库存、财务、生产、人事、项目、客户与供应商协同等多个业务环节。如果各业务模块分散管理，容易出现数据重复录入、库存不准确、财务对账困难、生产进度不透明、审批流程混乱等问题。

本系统目标是建设一套统一的 ERP 管理平台，实现企业核心业务流程线上化、数据集中化、权限规范化、经营可视化。

3. 用户角色
3.1 老板 / 管理层
主要关注企业经营数据和决策分析。

核心需求：

查看经营看板

查看生产进度
查看项目进度
查看员工、人效、审批统计
查看异常预警
3.2 业务人员
包括销售、采购、仓库、财务、生产、人事、项目人员等。

核心需求：

录入和处理业务单据
跟进客户、订单、采购、库存、生产、项目

查看本人相关数据
处理待办事项
3.3 系统管理员
负责系统基础配置和权限维护。

核心需求：

用户管理

按钮权限管理
API 权限管理
组织架构管理
字典配置
系统参数配置
操作日志查看
3.4 外部客户 / 供应商
用于后续外部协同。

核心需求：

客户查看订单、合同、项目进度、售后
供应商查看采购订单、送货、对账信息

12. 验收标准
12.1 采购流程验收
能创建采购订单
能审批采购订单
能根据采购订单入库
入库后库存增加
自动生成应付账款
能查看采购统计
12.2 销售流程验收
能创建销售订单
能审批销售订单
能根据销售订单出库
出库后库存减少
自动生成应收账款
能登记客户回款
能查看销售统计
12.3 库存流程验收
能查询实时库存
能查看库存流水
能进行库存调拨
能进行库存盘点
能触发库存预警
12.4 财务流程验收
能查看应收账款
能查看应付账款
能登记收款
能登记付款
能进行客户 / 供应商对账
能统计利润
12.5 生产流程验收
能维护 BOM
能创建生产工单
能根据工单领料
领料后库存减少
能进行完工入库
完工后成品库存增加
12.6 权限验收
不同角色登录看到不同菜单
无权限用户不能访问接口
不同部门只能查看授权范围内数据
敏感操作有日志记录
13. 总结
该 ERP 系统首期应优先围绕 进销存 + 财务 + 权限 + 基础资料 建立业务闭环，再逐步扩展到 生产制造、人事办公、项目管理、客户/供应商协同。

推荐开发顺序：


系统权限 → 基础资料 → 采购管理 → 销售管理 → 库存管理 → 财务管理 → 报表看板 → 生产 / 人事 / 项目 / 外部门户
这样可以先保证企业最核心的经营数据流转起来，再逐步完善高级业务能力。
